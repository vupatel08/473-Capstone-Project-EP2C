# Logic Analysis for **refinement_controller.py**

## Purpose & Overview
`refinement_controller.py` serves as the core orchestrator implementing the iterative PDDL refinement process described in Algorithm 1. It manages initialization, candidate generation, exploration walk sampling, environment interactions, EW scoring, and candidate selection, guiding the refinement loop toward high-fidelity environment models for solving planning problems.

## Main Responsibilities
- Initialize the PDDL domain and problem definitions (`d`, `p`) based on NL descriptions.
- Generate multiple candidate domain/problem files per iteration using GPT-4 via prompts.
- For each candidate:
  - Sample multiple random action sequences (exploration walks, EW).
  - Evaluate executability (`E_{d,p}`) and compute EW scores.
  - Run classical planner (`C`) with candidate PDDL files.
  - Validate generated plan against ground-truth environment using `V_{d,p}`.
- Select the candidate with the highest EW score and plan success.
- Incorporate environment feedback (`f(c)`) into subsequent refinements.
- Repeat until maximum iterations or convergence criteria are met.
- Output final PDDL files, plans, and metrics.

## Input & Configuration
- **NL environment description** (`nl_descriptions`)
- **NL task description** (`nl_task`)
- **Dataset info** for environment object list, environment API interface.
- **Parameters:**
  - `n_p` (candidate problem count)
  - `n_d` (candidate domain count)
  - `c_max` (max refinement cycles)
  - `T_max` (exploration walk length)
- **Prompt templates** for initial generation, refinement, and problem creation.
- **Interfaces** for:
  - GPT API calls (`generate_response`)
  - Environment interaction (`execute_action`, `check_executability`, `validate_plan`)
  - Classical planner (`run_planner`)
  - PDDL utilities (`parse_pddl`, `validate_syntax`, `write_pddl_files`)

## Key Components & Their Functions
### 1. Initialization (`initialize()`)
- Generate initial NL prompts for domain and problem.
- Use GPT-4 with temperature = 0.0 to create initial `d(0)`, `p(0)`.
- Save initial PDDL files.
- Return `current_domain`, `current_problem` as the current best candidates.

### 2. Candidate Generation (`generate_candidates()`)
- For each candidate (domain and problem pair):
  - Construct prompt using current best PDDL `d`, `p`.
  - Call GPT-4 to produce multiple versions (`n_d`, `n_p`) with variation.
  - Validate syntax with `validate_syntax()`.
  - Store valid candidate strings.

### 3. Exploration Walk Sampling (`sample_action_sequences()`)
- For each candidate (`d`, `p`):
  - For each problem instance:
    - Repeatedly sample action sequences (`T_max` steps).
    - Use `check_executability()`:
      - Simulate executing actions in the environment.
      - Record whether sequence is executable (`E_{d,p}`).
    - Collect `q_{1:T}` sequences and their executability labels.
- Generate a set of candidate action sequences for EW score evaluation.

### 4. EW Score Computation (`compute_ew_score()`)
- For each candidate:
  - Sample multiple action sequences (`q_{1:T}`).
  - For each sequence:
    - Check executability in environment: `E_{d,p}(q)`.
  - Calculate the fraction of executable sequences over total (`EW` score), normalized to [0, 1].
- The score indicates how well the PDDL model aligns with environment actions.

### 5. Candidate Evaluation & Selection (`select_best_candidate()`)
- Run the classical planner for each candidate (`run_planner()`):
  - Generate plan from `d`, `p`.
  - Validate plan with real environment feedback (`V_{d,p}`).
  - Record success or failure.
- Pick candidate with the highest EW score and plan success rate.
- Update best domain/problem files accordingly.

### 6. Refinement Step (`refine()`)
- Use environment feedback (`f(c)`), e.g., from failed exploration or invalid plans.
- Generate an environmental feedback prompt (`generate_refinement_prompt()`).
- Use GPT-4 to produce improved `d` and `p`.
- Validate syntax, store as current candidate.
- Loop back for next refinement cycle.

### 7. Main Execution (`execute_refinement()`)
- Control the iteration loop:
  - Call candidate generation.
  - Sample actions, compute EW scores.
  - Run planning/validation.
  - Select best candidate.
  - Generate next set of candidates.
  - Terminate if convergence or `c_max` reached.
- Collect and store:
  - Final PDDL files.
  - Task solve rates.
  - EW scores.
  - Plan success metrics.

## Handling Environment & External Calls
- Use `environment.py`:
  - `check_executability(q)`: returns boolean, simulating environment tests.
  - `execute_action(action)`: performs actions in environment, updates state.
  - `validate_plan(plan)`: verifies plan validity.
- Use `planner_interface.py`:
  - Run external classical planner (`run_planner(d, p)`), parse plan output.
- Use `pddl_utils.py`:
  - Validate syntactic correctness of generated PDDL.
  - Extract predicate info if needed for prompts.
- Use GPT API via a dedicated function, with prompt structure inspired by Appendix A.

## Error Handling & Robustness
- Syntax validation: reject syntax errors, regenerate with prompts.
- Handle invalid or incomplete PDDL code via retries.
- During sampling, discard sequences that fail executability checks early.
- When no plans found, record as plan failure; use feedback to improve.

## Metrics & Reporting
- After iterations:
  - Compute overall solve rate: number of environments/tasks solved.
  - Average EW score.
  - Correlation between EW and success.
- Save best PDDL files, plans, and logs.

## Additional Notes
- Always ensure data consistency: object names, predicate definitions.
- Maintain clear separation of concern:
  - Prompt generation (prompt_manager.py)
  - PDDL processing (pddl_utils.py)
  - Environment interaction (environment.py)
  - Planning (planner_interface.py)
  - Iteration logic (refinement_controller.py)
- Flexibility:
  - Capable of handling multiple seeds for robustness.
  - Configurable parameters via `config.yaml`.
- Final outputs:
  - Refined `d` and `p` files.
  - Metrics for performance comparison.

## Summary
`refinement_controller.py` implements the core logic of Algorithm 1, combining GPT-4-driven generation, environment feedback, exploration sampling, plan execution, and iterative refinement. It orchestrates multiple interdependent modules to produce PDDL models aligned with real environment behavior, optimizing task solve rate across potentially noisy or incomplete model initializations. Careful handling of prompts, environment API interactions, syntax validation, and candidate evaluation is essential for success.
