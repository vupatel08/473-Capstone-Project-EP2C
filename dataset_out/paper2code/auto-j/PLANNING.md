# Planning Phase

This document contains the complete planning phase output, including the overall plan, architecture design, logic design, and configuration.

## 1. Overall Plan

Certainly! Here is a comprehensive, detailed plan to reproduce the methodology and experiments described in the paper titled "GENERATIVE JUDGE FOR EVALUATING ALIGNMENT" (AUTO-J). This outline covers dataset construction, model training, evaluation protocols, and experiment settings, focusing on aligning with all technical nuances explicitly mentioned or implied.

---

## 1. Overall Approach Summary
- **Objective:** Develop and evaluate an open-source generative judge model (AUTO-J) with 13B parameters capable of performing both pairwise response comparison and single-response evaluation, with well-structured critiques.
- **Methodology Steps:**
  - Collect a diverse, scenario-rich dataset from real-world user queries and LLM responses.
  - Annotate supervision signals using GPT-4 with curated evaluation criteria.
  - Train AUTO-J on scenario-aware data, optimizing for accuracy, flexibility, and explainability.
  - Evaluate using multiple protocols: pairwise comparison, single-response rating, and overall agreement metrics against human and GPT-4 annotations.

---

## 2. Data Construction Pipeline
### 2.1 Scenario and Criteria Definition
- **Define 58 distinct evaluation scenarios** (e.g., summarization, code rewriting, creative writing, etc.).
- Use the detailed scenario taxonomy (as in Fig. 2) to create targeted prompts and criteria.
- **Create scenario-specific evaluation criteria** (~332 total) with structured guidelines for responses.
- For each scenario:
  - Formalize both basic and scenario-aware annotation criteria.
  - Store these as system-instruction prompts for GPT-4 or similar LLMs to generate annotations.

### 2.2 Collect Data Samples
- **Sources:**
  - User queries from real-world data
  - Responses generated by strong open-source LLMs **(Vicuna-13B, LLaMA-2-Chat-13B, WizardLM, etc.)**.
  - Synthetic data: Generate ~30K+ scenario responses per dataset (training, validation, test).
- **Sample Size Goals:**
  - Total pairwise samples: ~999k (e.g., 58 scenarios × ~17k pairs, as in Tab. 7, 8).
  - Single responses: ~50k+ per scenario for rating sets (per Tab. 23, 25).
- **Data Format:**
  - Each sample includes: 
    - Query/input
    - Response(s) (pair or single)
    - Scenario label
    - Response annotation (optional, GPT-4 generated critique/rating)
  - For pairwise data, generate responses from different models and/or with different prompt variants.

### 2.3 Annotation Processes
- **Supervision Signals:** 
  - Use GPT-4, prompted with scenario criteria (Tab. 16, 18) to annotate responses.
  - For pairwise responses:
    - Curate a prompt (Tab. 19) to GPT-4 to decide which response is better, extracting critique and a yes/no preference.
  - For single responses:
    - Curate prompts (Tab. 18, 20) for GPT-4 to generate critiques and overall ratings (1–10 scale).
- **Automation:**
  - Automate GPT-4 API calls for large-scale annotation, with heuristics to filter noise (heuristic filtering + postprocessing).
- **Data Quality Control:** 
  - Filter responses via heuristic thresholds.
  - Remove ambiguous or low-confidence annotations.
  - Optionally, human review on a subset for validation.

---

## 3. Model Training
### 3.1 Model & Architecture
- Use a tokenizer and transformer architecture aligned with LLaMA-2-13B (or comparable open-source models).
- Implement a sequence-to-sequence or decoder-only architecture capable of causal generation.
- Initialize from a pre-trained large language model (like LLaMA-2-13B).

### 3.2 Data Preparation
- **Scenario-aware data:**
  - For each sample, prepend the scenario-specific instruction/criteria prompt (Tab. 16, 18) as input context to GPT-4-generated annotations.
  - For pairwise: Concatenate responses with scenario prompt, asking GPT-4 to compare.
  - For single-response: Include scenario prompt to guide critique/rating generation.
- **Input Formatting:**
  - Tokenize entire input (query + scenario criteria + response(s)).
  - For pairwise, create two separate samples or a combined prompt with both responses.
  - For single-response evaluation, system prompt + response + instructions.

### 3.3 Training Objectives
- **Supervised Fine-tuning:**
  - **Pairwise Response Comparison:** Train classifier/regressor to predict preference (win/tie/lose) based on scenario-specific prompt plus responses.
  - **Single-response rating:** Train regression model to output a 1–10 score, matching GPT-4 annotations.
  - **Critique Generation:** Fine-tune to generate critiques aligned with GPT-4 critiques (for interpretability).

### 3.4 Hyperparameters & Training Setup
- Use the AdamW optimizer.
- Learning rate warm-up over first 6.75k steps (~0.9% of total steps), decay exponentially.
- Batch size: 64 sequences per step.
- Learning rate decay: 0.95 per epoch or as per best validation performance.
- Number of epochs: ~5 (each epoch ~6750 steps).
- Checkpoints every 50 steps.
- Use mixed precision (fp16 and fp32 parts) with gradient checkpointing for memory efficiency.
- Use a custom hyperparameter search with Bayesian optimization (e.g., AdamW variants as in Tab. 18).

## 4. Evaluation Protocols
### 4.1 Pairwise Response Comparison
- **Test Dataset:**
  - Use the 58 scenario test set (Tab. 7).
  - Generate pairs from model responses (from different models or prompt variants).
- **Metrics:**
  - Win rate against baselines (GPT-4 judgments, human judgments as in Sec. 6.1, 6.2).
  - Measure consistency and agreement with GPT-4 and human labels.
- **Implementation:**
  - Use the trained model to infer preferences for each pair.
  - Compare with GPT-4 preferences (via API or simulation) as in Tab. 1.

### 4.2 Single-Response Rating
- **Test Dataset:**
  - Use the 58 scenarios' responses (Sec. 6.2, Tab. 23).
  - Generate ratings from our model, GPT-4, and human annotations.
- **Metrics:**
  - Correlation (Pearson, Spearman) with human and GPT-4 labels.
  - Agreement rates (as in Tabs. 22, 25).
- **Procedures:**
  - Evaluate at the response level across scenarios.
  - Calculate consistency and correlation metrics.

### 4.3 Overall System-Level Agreement
- Use the aggregate scores (e.g., GT4 win rate, overall agreement as in Sec. 6.1, 6.2, 6.3).
- Reproduce the statistical tests (e.g., compare AUTO-J & GPT-4 vs. baselines).

---

## 5. Experimental Setup & Hyperparameters
- **Hardware:**
  - Use 8+ Nvidia A100-40GB GPUs; memory considerations addressed via gradient checkpointing.
- **Software Framework:**
  - Implement on HuggingFace Transformers + DeepSpeed or PyTorch Lightning.
  - Use pre-trained weights from open-source models as initializers.
- **Hyperparameters:**
  - Model size: 13B parameters.
  - Learning rate: tuned around 1e-5, with decay.
  - Batch size: 64.
  - Max sequence length: 2048 tokens.
  - Number of epochs: 5.
- **Training schedule:**
  - Warm-up over ~6.75k steps.
  - Exponential decay of LR.
  - Use validation at checkpoints (every 50 steps) with early stopping if needed.

---

## 6. Additional Considerations
- **Scenario Diversity & Balance:**
  - Ensure training, validation, and testing datasets are representative (~58 scenarios + some "others" category).
  - Maintain balanced samples across scenarios.
- **Quality of Annotations:**
  - Filter GPT annotations for noise heuristics (e.g., confidence thresholds).
  - Use human review for a subset to assess quality.
- **Reproducibility:**
  - Set seed values.
  - Fix random states.
  - Keep detailed logs of hyperparameters and training steps.

## 7. Future Extensions & Robustness
- Evaluate scenario generalization on unseen scenarios (Sec. 6.4, Tab. 24–28).
- Use cross-validation or multiple runs to assess stability.
- Incorporate scenario-agnostic slope (as in Sec. 6.4, Tab. 28) for robustness.
