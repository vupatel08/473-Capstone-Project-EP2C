# Planning Phase

This document contains the complete planning phase output, including the overall plan, architecture design, logic design, and configuration.

## 1. Overall Plan

To accurately reproduce the Self-Play Fine-Tuning (SPIN) methodology outlined in the paper, your implementation plan should systematically cover the following core components:

---

### 1. **Framework and Core Concept**
- **Self-play mechanism**: Leverages iterative interaction where the current model (main player) tries to distinguish responses of its previous version (opponent) from human data, and then updates itself to better imitate the data distribution.
- **Key objective**: Minimize the divergence between the model's response distribution and the groundtruth data, with the convergence point being the model matching the data distribution (`p_theta(y|x) = p_data(y|x)`).

---

### 2. **Model Architecture & Initialization**
- **Base model**: Use an existing pre-trained large language model (e.g., Mistral-7B, GPT-2-sized or larger), fine-tuned on an initial supervised dataset (`SFT`).
- **Starting point**: Initialize the model with supervised fine-tuning (SFT) on a human-labeled dataset, or potentially on synthetic data generated from the pretrained model (e.g., Ultrachat data).
- **Opponent**: At each iteration, the opponent is the model from the previous iteration, which remains fixed during the current iteration's training.

---

### 3. **Datasets & Data Preparation**
- **Initial dataset (`SFT`)**:  
  - Select or construct a small but high-quality dataset of `(prompt, response)` pairs (e.g., Ultrachat 200K, or a similar benchmark dataset).
  - Sampling: 50K prompts are randomly selected from the dataset for generation.
- **Synthetic data generation**:  
  - From the current model, generate responses to prompts.
  - Generate responses via autoregressive decoding strategies (e.g., Greedy, Top-k, or Nucleus sampling).
  - For iteration 0, generate responses using the *initial fine-tuned* model.
  - For subsequent iterations, generate responses with the latest model.

- **Response pairs for training**:
  - The model generates responses that are tagged as responses of the *main player*.
  - The outdated model responses serve as the *opponent* responses.
  - Human responses (if available) serve as the groundtruth; if not, synthetic responses from the initial model serve as baseline data.

---

### 4. **Implementation of the Self-play Step**
- **Distinguishing network** (`f_{t+1}`):
  - Architecture: An auxiliary classifier (e.g., a smaller neural network or a linear head) that takes `(prompt, response)` pairs and outputs a scalar score indicating "real" (human/hard data) vs. "fake" (model responses).
  - **Training objective**: Maximize the expected difference in responses generated by the current model (opponent from previous iteration) and ground-truth human data.

- **Training the response generator (main model)**:
  - **Loss function**: Negative log-likelihood (or a variational objective as derived), approached via KL divergence minimization. Combine with the adaptive reweighting term derived from the model responses and the groundtruth synthetic/human data.
  - Use the formula from paper (eq. 4.2 and 4.4):  
    \[
    L_{\text{SPIN}}(\theta, \theta_t) \propto \mathbb{E}_{x, y, y'}\bigg[ \ell\bigg( \lambda \log \frac{p_\theta(y|x)}{p_{\theta_t}(y|x)} - \lambda \log \frac{p_\text{data}(y'|x)}{p_{\theta_t}(y'|x)} \bigg) \bigg]
    \]
  - Approximations:  
    - For practical implementation, use a neural model (the main response generator) trained to produce responses that the discriminator can't distinguish from data.
    - Use the derived softmax formula, where the updated model responds more closely to `p_data`.

---

### 5. **Updating the Opponent (Model from previous iteration)**
- **Closed-form update**: As per eq. (4.6), update the model via a reweighting of the previous distribution:
  \[
  p_{\theta_{t+1}}(y|x) \propto p_{\theta_t}(y|x) \left(\frac{p_\text{data}(y|x)}{p_{\theta_t}(y|x)}\right)^{1/\lambda}
  \]
- **Practical implementation**:
  - During training, approximate this update by fine-tuning the model to respond with responses weighted by response scores (e.g., the discriminator scores), effectively implementing the exponential reweighting.
  - Fine-tune the model parameters to realize this distribution, with regularization (e.g., KL) to maintain model stability.

---

### 6. **Iterative Process & Convergence**
- **Iterations**:
  - Repeat the cycle: generate responses, train discriminator, update the main model (`\theta_{t+1}`), and set `\theta_{t+1}` as the new opponent.
  - Perform multiple iterations (e.g., 0 to 3 as in the experiments, possibly more for convergence analysis).

- **Stopping criterion**:
  - Model responses plateau with respect to performance on validation tasks.
  - The response distribution matches the data distribution (`p_{theta}(y|x) ≈ p_data(y|x)`).

---

### 7. **Hyperparameters & Settings**
- **Number of iterations**: Typically 3-4.
- **Learning rate**:
  - For response generator fine-tuning: Use a small learning rate (e.g., 1e-5 to 3e-5).
- **Response generation**:
  - Sampling method: Greedy, top-k, or nucleus sampling; tune temperature accordingly.
- **Discriminator**:
  - Architecture: Lightweight model (e.g., small transformer or MLP) or a linear layer on token embeddings.
  - Objective: Discriminate between human/groundtruth responses and model responses.
- **Loss functions**: Use a monotonic, convex loss like logistic or BTL-based loss (as described, with the specific $\ell(t) = \log(1 + \exp(-t))$).
- **Batch sizes**:
  - Generate responses in batches suitable to GPU memory (e.g., 32–128 prompts per batch).
  - Fine-tune with small batch sizes if necessary, or gradient accumulation.
- **Response length**:
  - Match the typical response length of the dataset or from initial data generation (e.g., 50–200 tokens).
- **Regularization**:
  - KL divergence regularization with coefficient $\lambda$ (e.g., 0.1–0.2).

---

### 8. **Evaluation Metrics & Benchmarks**
- **Main performance metrics**:
  - **Open LLM Leaderboard**: Accuracy or composite scores across datasets like Arc, TruthfulQA, Winogrande, GSM8K, HellaSwag, MMLU.
  - **Other Reasoning Tasks**: MT-Bench, Big-Bench, OpenBookQA.
- **Evaluation protocol**:
  - Zero-shot or few-shot evaluation using the same prompts as original datasets.
  - Use the official leaderboards and scoring scripts to ensure comparability.
- **Comparison baselines**:
  - Original SFT baseline.
  - Additional models trained with RLHF or on larger datasets.
  - SFT with additional epochs (to show the benefit of SPIN).

---

### 9. **Implementation Checklist**
- **Environment setup**:  
  - Deep learning framework: PyTorch or TensorFlow.
  - Model APIs: HuggingFace Transformers or custom APIs for large models.
- **Data loading**:  
  - Load or simulate datasets (Ultrachat, etc.).
  - Ensure efficient response generation with batching.
- **Model training loop**:
  - Generate synthetic responses conditioned on prompts.
  - Train discriminator to distinguish responses.
  - Compute the updated response distribution (via sampling or reweighting).
  - Fine-tune the main model on the new synthetic data, incorporating the derived loss.
- **Iteration management**:
  - Save model checkpoints after each iteration.
  - Log training and validation performance to detect convergence.
- **Hyperparameter tuning**:
  - Conduct small grid searches on $\lambda$, response length, learning rate, and sampling parameters.
- **Validation and testing**:
  - Evaluate on held-out prompts and datasets.
  - Check for signs of mode collapse or degeneration.

---

### **Summary:**
Your implementation plan should:
- Start with an initial SFT model trained on available human or synthetic data.
- Generate responses for prompts from this model.
- Train a discriminator to distinguish generated responses from real/human responses.
- Use the discriminator scores to reweight responses, aligning the response distribution closer to the data.
- Fine-tune the model using the derived weighted response distribution (effectively implementing the closed-form solution).
- Iterate the above process multiple times, each time updating the opponent (model from previous iteration).
- Evaluate thoroughly on benchmark datasets matching the paper's settings, adjusting hyperparameters based on validation performance.

This comprehensive roadmap aligns closely with the paper's theoretical and experimental details, ensuring a robust foundation for coding and implementing the SPIN method later.
