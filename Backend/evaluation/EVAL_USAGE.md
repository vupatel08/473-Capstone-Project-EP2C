# Paper2Code Evaluation Usage Guide

This guide explains how to use the `eval.py` script to evaluate generated code repositories against research papers.

## Prerequisites

1. **OpenAI API Key**: Set your `OPENAI_API_KEY` environment variable or in `.env` file
2. **Generated Repository**: A code repository generated by the EP2C pipeline
3. **Paper File**: The parsed paper (JSON or markdown) from the pipeline

## Basic Usage

### 1. Reference-Free Evaluation (Recommended for most cases)

Evaluates your generated code directly against the paper without needing a gold repository.

```bash
python Backend/paper2code/eval.py \
    --paper <path_to_paper> \
    --target_repo <path_to_generated_repo> \
    --output evaluation_results.json
```

**Example with unified pipeline output:**
```bash
python Backend/paper2code/eval.py \
    --paper Backend/example_driver/outputs/paper2code/MyPaper/parse_output/MyPaper/auto/MyPaper.md \
    --target_repo Backend/example_driver/outputs/paper2code/MyPaper/MyPaper_repo \
    --gpt_version gpt-4o \
    --output Backend/example_driver/outputs/paper2code/MyPaper/evaluation_results.json
```

### 2. Reference-Based Evaluation (When you have a gold repository)

Compares your generated code against a known-good reference implementation.

```bash
python Backend/paper2code/eval.py \
    --paper <path_to_paper> \
    --target_repo <path_to_generated_repo> \
    --gold_repo <path_to_gold_repo> \
    --output evaluation_results.json
```

**Example:**
```bash
python Backend/paper2code/eval.py \
    --paper Backend/example_driver/outputs/paper2code/MyPaper/parse_output/MyPaper/auto/MyPaper.md \
    --target_repo Backend/example_driver/outputs/paper2code/MyPaper/MyPaper_repo \
    --gold_repo Backend/example_driver/github_repo/MyPaper-main \
    --gpt_version gpt-4o \
    --output Backend/example_driver/outputs/paper2code/MyPaper/evaluation_results.json
```

## Integration with Unified Pipeline

After running the unified pipeline, you can evaluate the generated repository:

```python
from Backend.unified_pipeline import run_unified_pipeline
from Backend.paper2code.eval import evaluate_from_pipeline

# Run the pipeline
result = run_unified_pipeline(
    paper_pdf_path="path/to/paper.pdf",
    paper_name="MyPaper",
    gpt_version="o3-mini"
)

# Evaluate the generated repository
eval_result = evaluate_from_pipeline(
    paper_path=result["paper_md_path"],  # Use paper from pipeline
    target_repo_path=result["repo_path"],  # Use generated repo from pipeline
    gpt_version="gpt-4o",
    output_path=f"{result['output_dir']}/evaluation_results.json"
)

print(f"Evaluation Score: {eval_result['score']}/5")
print(f"Number of Critiques: {len(eval_result.get('critique_list', []))}")
```

## Command-Line Arguments

| Argument | Required | Description |
|----------|----------|-------------|
| `--paper` | Yes | Path to paper JSON or markdown file |
| `--target_repo` | Yes | Path to target (generated) repository directory |
| `--gold_repo` | No | Path to gold (reference) repository (enables ref-based eval) |
| `--gpt_version` | No | GPT model version (default: `gpt-4o`) |
| `--output` | No | Output JSON file path (default: prints to stdout) |

## Output Format

The evaluation returns a JSON dictionary with the following structure:

```json
{
  "evaluation_type": "ref_free",
  "score": 4,
  "critique_list": [
    {
      "file_name": "model.py",
      "func_name": "forward",
      "severity_level": "medium",
      "critique": "The loss function implementation differs from the paper..."
    },
    {
      "file_name": "trainer.py",
      "func_name": "train_step",
      "severity_level": "low",
      "critique": "Learning rate schedule could be improved..."
    }
  ],
  "paper_path": "path/to/paper.md",
  "target_repo_path": "path/to/repo"
}
```

### Score Interpretation

- **5 (Excellent)**: Fully and accurately implements all key components
- **4 (Good)**: Correctly implements key components with minor inaccuracies
- **3 (Fair)**: Some core components correct, but notable errors
- **2 (Poor)**: Significant mistakes or missing components
- **1 (Very Poor)**: Major logical errors or missing core concepts

### Severity Levels

- **High**: Missing or incorrect core concepts, major algorithms
- **Medium**: Issues affecting training logic, data preprocessing
- **Low**: Minor issues like logging, evaluation metrics, hyperparameters

## Examples

### Example 1: Evaluate after pipeline run

```bash
# 1. Run the unified pipeline
python Backend/unified_pipeline.py \
    --paper_pdf path/to/paper.pdf \
    --paper_name MyPaper

# 2. Evaluate the generated repository
python Backend/paper2code/eval.py \
    --paper Backend/example_driver/outputs/paper2code/MyPaper/parse_output/MyPaper/auto/MyPaper.md \
    --target_repo Backend/example_driver/outputs/paper2code/MyPaper/MyPaper_repo \
    --output Backend/example_driver/outputs/paper2code/MyPaper/evaluation_results.json
```

### Example 2: Batch evaluation script

```python
import json
from pathlib import Path
from Backend.paper2code.eval import evaluate_from_pipeline

# Load dataset info
with open("Backend/paper2code/dataset_info.json") as f:
    dataset_info = json.load(f)

# Evaluate multiple papers
results = {}
for conference, papers in dataset_info.items():
    for paper_info in papers:
        paper_name = paper_info["repo_name"]
        output_dir = Path(f"Backend/example_driver/outputs/paper2code/{paper_name}")
        
        paper_path = output_dir / "parse_output" / paper_name / "auto" / f"{paper_name}.md"
        repo_path = output_dir / f"{paper_name}_repo"
        
        if paper_path.exists() and repo_path.exists():
            print(f"Evaluating {paper_name}...")
            result = evaluate_from_pipeline(
                paper_path=str(paper_path),
                target_repo_path=str(repo_path),
                gpt_version="gpt-4o",
                output_path=str(output_dir / "evaluation_results.json")
            )
            results[paper_name] = result["score"]
            print(f"  Score: {result['score']}/5")

# Save summary
with open("evaluation_summary.json", "w") as f:
    json.dump(results, f, indent=2)
```

## Tips

1. **Use reference-based evaluation** when you have access to the original GitHub repository for more accurate comparisons
2. **Use reference-free evaluation** for general quality assessment when no gold standard is available
3. **Check the critique list** for specific issues to fix in your generated code
4. **Use `gpt-4o`** for best evaluation quality (default), or `gpt-4-turbo` for faster/cheaper evaluation
5. **The script handles rate limits** automatically with retry logic

## Troubleshooting

### Error: OPENAI_API_KEY not found
```bash
export OPENAI_API_KEY=your_key_here
# Or add to .env file in Backend/ directory
```

### Error: Paper file not found
- Make sure the paper was parsed by the unified pipeline
- Check the path in `output_dir/parse_output/<paper_name>/auto/<paper_name>.md`

### Error: Repository not found
- Ensure the coding phase completed successfully
- Check the path in `output_dir/<paper_name>_repo`

### Rate limit errors
- The script automatically retries with exponential backoff
- Consider using a model with higher rate limits or reducing batch size
