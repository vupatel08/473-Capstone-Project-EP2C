Reproduction Plan for "Autoregressive Image Generation without Vector Quantization" (Mar)

---

### 1. Overview and Goals  
The paper proposes a novel method for autoregressive image generation that *avoids the use of vector-quantized tokens*, instead utilizing **continuous-valued tokens modeled via diffusion**. The primary innovations include:
- Replacing discrete token prediction with a *Diffusion Loss* (based on denoising diffusion models).
- Using a **Transformer-based autoregressive framework**, adaptable to both standard causal and masked autoregressive variants.
- Achieving fast inference with high-fidelity generated images on ImageNet 256×256.

Our reproduction aims to replicate the entire pipeline:
- Data preprocessing and tokenization.
- Model architectures (Transformer, denoising MLP).
- Diffusion process (training and inference).
- Autoregressive and masked autoregressive variants.
- Evaluation metrics (FID, IS, Precision/Recall).

---

### 2. Dataset and Data Preparation

**Dataset:**
- Use **ImageNet (i.i.d. training/validation splits)** at resolutions:
  - 256×256 pixels for main experiments.
  - (Optional) 512×512 for scaled experiments.
- For a baseline, download the publicly available ImageNet dataset, ideally using a well-curated, preprocessed subset as per the original authors (assuming their code uses standard ImageNet processing).

**Preprocessing:**
- Resize images to 256×256.
- Normalize images according to standard ImageNet data (mean/std normalization if needed for certain tokenizers).
- For tokenization, utilize **existing pre-trained tokenizers**:
  - VQ-16 (VQ-GAN style VQ-VAE tokens, K=16, stride=16).
  - KL-16 (KL divergence regularized tokens, same stride).
  - Optionally, KL-8 (stride=8, shorter sequence length) for testing mismatched stride.
- Note the importance:
  - The tokenizers produce either discrete tokens (integers in [0, K-1]) or continuous embeddings (pre-encoded).
  - Use the **public code for tokenizers from the LDM repository** or equivalent.

**Important:**
- If reproducing the tokenizer, ensure it matches the original parameters (e.g., the same stride, codebook size).
- For modeling pixel-based tokens directly (D.3), group every 4×4 pixel block into a token (for 64×64 resolution).

---

### 3. Tokenizer and Data Representation

- Download and set up **VQ-16 and KL-16 tokenizers** from the publicly available LDM codebase.
- For each image:
  - Encode using the tokenizer to produce a sequence of tokens.
  - For continuous token modeling (our goal), treat the *latent features* before the final quantization layer as "continuous tokens" (per the paper's diffusing on entailed 'latent' space).
  - For pixel-based modeling (less aligned with original scope): group 4×4 pixels into a token, resulting in sequences of length ~1024.

### 4. Model Architecture

**a. Transformer Backbone:**
- Implement a **Transformer (ViT-style)**, matching the paper:
  - 32 blocks, width = 1024 (large-size variant).
  - Add positional embeddings (sine or learned).
  - Append a class token ([cls]) for autoregressive conditioning.
- Input tokens:
  - For VQ tokens: integer tokens (with embedding layer).
  - For continuous tokens: normalized real-valued vectors.
- Use **causal attention** for baseline AR:
  - Masked to prevent future tokens' information.
- For masked autoregressive (MAR) variants:
  - Use **bidirectional attention** with masking to predict multiple tokens simultaneously.
  - Incorporate mask tokens in decoder.

**b. Denoising MLP (Diffusion Head):**
- Small MLP (e.g., 3 residual blocks):
  - Layers: LayerNorm → Linear → SiLU → Linear
  - Residual connection.
- Input:
  - Noise-corrupted token x_t (vector), timestep t (scalar embedding), condition vector z.
- Conditioning:
  - z is the output of the autoregressive network for each token (or global for the sequence).
- Architecture considerations:
  - 1024 channels, 3 blocks.
  - Condition added via AdaLN or similar adaptive normalization.

**c. Diffusion Process:**
- Based on DDPM:
  - Noise schedule: cosine form, 1000 steps during training.
  - At inference, sample fewer steps (~100).
- Loss:
  - Predict the noise added to x at each step (εθ).
  - Use MSE between predicted noise and true noise.
- Training:
  - For each token, add noise at a randomly sampled timestep t.
  - Optimize the denoising network parameters jointly with the autoregressive model via backpropagation.

**d. Tokenizers:**
- Use pre-trained VQ-GAN (VQ-16) or KL-divergence trained tokenizer.
- For models trained on continuous token spaces, treat encoder outputs as real-valued vectors.
- For models that incorporate mismatched stride tokenizers, carefully adjust sequence length and positional embedding accordingly.

---

### 5. Training Procedures

**a. Autoregressive Model:**
- Train either:
  - **Causal Transformer** (causal attention): predict x_i conditioned on previous tokens.
  - Or **MAR variant** (masked bidirectional attention): randomly mask tokens during training.
- Inputs:
  - Token sequences (either discrete tokens or continuous features).
- Targets:
  - The same tokens with diffusion process applied.
- Optimization:
  - AdamW optimizer:
    - Learning rate: 8e-4
    - Batch size: 2048
    - Epochs: 400
    - Warmup: 100 epochs
    - Weight decay: 0.02
    - EMA of parameters: rate 0.9999
- Loss:
  - Diffusion loss as per Eqn. (1):
    - Sample t uniformly, corrupt token x with noise.
    - Compute εθ(x_t, t, z).
    - Minimize MSE.
- Classifier-free guidance:
  - During training, 10% of samples replace class embedding with a dummy token.

**b. Diffusion Network Training:**
- For each token in a batch:
  - Compute noisy x_t from ground truth.
  - Predict noise εθ(x_t, t, z).
- Inline with diffusion model training conventions.
- Use the same schedule and parameters as standard DDPM implementations.

---

### 6. Inference Procedures

**a. Autoregressive Sampling:**

- For causal AR:
  - Generate tokens sequentially, from start to finish.
  - For each token:
    - Compute z via the autoregressive network given previous tokens.
    - Run reverse diffusion (sampling) conditioned on z:
      - Initialize x_T ~ N(0, I).
      - For t in T to 1:
        - Denoise step:
          - x_{t-1} = 1/√α_t * [x_t - (1 - α_t) εθ(x_t, t, z)] + σ_t δ
      - Final x_0 gives the token.
- For efficiency:
  - Use cached computations for previous z (if possible).
  - Use 100 diffusion steps for inference, as per the paper.

**b. Masked/Parallel Prediction:**

- For MAR:
  - Follow cosine schedule to reduce masking ratio from 1.0 to 0 in 64 steps.
  - At each step:
    - Use the full bidirectional attention to predict all unknown tokens simultaneously.
    - Incorporate diffusion process conditioned on known tokens.
    - Use temperature τ and guidance (if needed).
  - Collate multiple tokens per step if predicting multiple tokens simultaneously.

### 7. Hyperparameters and Tuning

- Noise schedule: cosine shape, 1000 steps for training.
- Diffusion sampling steps: 100 steps (or as in the paper for high quality).
- Temperature τ: tune over [0.7, 1.0], default as per paper.
- Guidance scale ω: tune via validation or set default guidance following experiments (e.g., 4.0).
- Masking ratio, dropout, batch size, and learning rate as per description.

### 8. Evaluation Metrics and Protocols

- Use **FID** (via standard PyTorch/torchmetrics implementation) for image quality:
  - Evaluate on 50k generated images.
- Use **Inception Score (IS)** and **Precision/Recall**:
  - Following the same suite as [10].
- Reproduce quantitative results at comparable model sizes (~400M parameters) with same training durations (~400 epochs).

### 9. Implementation Notes and Ambiguities

- **Tokenizer Details:**  
  - The exact pre-trained models/parameters from the LDM repository are crucial.  
  - Confirm stride, codebook size, and architecture match.

- **Diffusion Process:**  
  - The exact noise schedule and hyperparameters should follow the cosine schedule in DDPM literature.  
  - If unavailable, tune β(t) schedulers accordingly.

- **Model Initialization:**  
  - Use Xavier or Kaiming initialization for transformer and MLP parameters.

- **Training Stability:**  
  - Use gradient clipping if necessary.  
  - Validate model convergence with smaller sample runs.

- **Speed and Resources:**  
  - The paper used 16 servers with 8 V100 GPUs; practical reproduction may involve similar setups or high-end GPUs like A100s.

- **Code and Data Accessibility:**  
  - While the paper does not provide code, they used publicly available tokenizers and standard diffusion training recipes.

### 10. Summary of Reproducibility Steps

1. Acquire and preprocess ImageNet at 256×256.
2. Obtain pre-trained VQ-16/KL-16 tokenizers, or train your own for consistency.
3. Encode all images to get token sequences.
4. Build a Transformer-based autoregressive model:
   - Use causal or masked attention.
   - Condition on previous tokens (or known tokens in MAR).
5. Implement the diffusion denoising head (small MLP).
6. Train the model jointly using diffusion loss:
   - Noise addition, predicting εθ, with appropriate schedule.
7. During inference, run either autoregressive token-by-token sampling via reverse diffusion or parallel masked prediction.
8. Generate images in the token space, decode to pixel images with the tokenizer decoder.
9. Evaluate with FID, IS, and record inference speed.
10. Compare with counterparts (discrete vs. continuous, AR vs. MAR).
