# Logic Analysis for planner_interface.py

## Purpose
- To provide an interface for invoking a classical PDDL planner (e.g., FastDownward).
- To check if a valid plan exists for given domain and problem PDDL files.
- To integrate smoothly with other modules, ensuring correct path setup, environment compatibility, and output parsing.

## Core Functions
### 1. run_planner(domain_file: str, problem_file: str) -> list of actions
- Executes the external planner with the given domain and problem PDDL files.
- Parses planner output into a sequence of actions or plans.
- Returns the plan as a list of structured actions or None if planning fails.

### 2. plan_exists(domain_file: str, problem_file: str) -> bool
- Checks whether a valid plan exists for the given inputs without returning the full plan.
- Typically, invokes the planner and interprets output codes/confirmations.

## Inputs and Outputs
- **Input:**
  - `domain_file`: Path to the domain PDDL file.
  - `problem_file`: Path to the problem PDDL file.
- **Output:**
  - For `run_planner`: a list of actions (parsed from output) if a plan exists; `None` or an empty list if no plan found.
  - For `plan_exists`: a boolean indicating the existence (`True`) or absence (`False`) of a plan.

## Implementation Details
- Use Python's `subprocess` module to execute the planner:
  - Compose command line instructions based on configuration parameters.
  - Capture stdout, stderr for parsing.
- Expect the planner to terminate with:
  - Exit code 0 on success with a plan.
  - Non-zero exit code or specific output pattern indicating failure.
- Plan parsing:
  - Extract the sequence of actions from the planner's output.
  - Convert the textual plan into a list of action strings or a structured format aligned with the environment API.

## Critical Considerations
### 1. Path Setup:
- The planner executable must be correctly referenced.
- Paths should be configurable via environment variables or hard-coded based on the config.
- Ensure that `planner_path` (if specified) is valid and accessible.

### 2. Environment Compatibility:
- On different platforms (Linux, Windows), subprocess invocation may differ.
- Ensure subprocess timeout handling for robustness.
  
### 3. Output Parsing:
- Design a robust parser:
  - Detect lines with actions.
  - Strip comments or non-action lines.
  - Convert each line into a move or action command compatible with the environment API.

### 4. Error Handling:
- Capture exceptions during subprocess calls.
- Handle timeouts.
- Provide clear logging or exceptions if the planner is missing or malfunctions.

### 5. Performance:
- Minimize reruns.
- Cache results if planning for the same domain/problem multiple times.

## Pseudocode Outline
```python
import subprocess
import os

class PlannerInterface:
    def __init__(self, planner_path: str):
        self.planner_path = planner_path

    def run_planner(self, domain_file: str, problem_file: str):
        try:
            command = [self.planner_path, '--search', 'astar', '--plan-file', 'plan.txt', domain_file, problem_file]
            result = subprocess.run(command, capture_output=True, text=True, timeout=300)
            if result.returncode != 0:
                # Planning failed, no plan
                return None
            plan = self._parse_plan('plan.txt')
            return plan
        except subprocess.TimeoutExpired:
            # Planning timed out
            return None
        except Exception as e:
            # Log or handle exceptions
            return None

    def plan_exists(self, domain_file: str, problem_file: str) -> bool:
        plan = self.run_planner(domain_file, problem_file)
        return plan is not None and len(plan) > 0

    def _parse_plan(self, plan_path: str):
        # Parse lines from the generated plan file
        actions = []
        with open(plan_path, 'r') as f:
            for line in f:
                line = line.strip()
                if line and not line.startswith(';'):  # Ignore comments
                    actions.append(line)
        return actions
```
