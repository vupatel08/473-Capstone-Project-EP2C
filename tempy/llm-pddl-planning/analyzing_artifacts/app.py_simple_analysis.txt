# Logic Analysis for app.py

This analysis provides a comprehensive and detailed guide for implementing the main script `app.py`, which orchestrates the entire process of environment dataset loading, initial PDDL generation, iterative refinement, plan execution, performance evaluation, and result reporting, in strict adherence to the methodology described in the paper, the configuration parameters, and the modular design.

---

## 1. Initialization Phase

### 1.1. Load Configuration
- Parse the `config.yaml` file using `PyYAML`.
- Extract relevant parameters:
  - `generation.n_p`, `generation.n_d`, `generation.c_max`, `generation.T_max`, `generation.temperature_initial`, `generation.temperature_refinement`.
  - `evaluation.plans_per_problem`, `evaluation.success_threshold`.
  - `prompting.initial_prompt_template`, `refinement_prompt_template`, `problem_prompt_template`.
  - `environment.api_base_url`.

### 1.2. Setup Data and Environment
- Instantiate a `DatasetLoader` class:
  - Load environment dataset: list of environment identifiers, each associated with ground-truth PDDL domain `d_true` and problems `p_{1:N}`.
  - Load NL descriptions for each environment: domain NL and problem NL.
  - Load ground-truth PDDL files for validation purposes.
- For each environment:
  - Create an `Environment` class instance:
    - Initialize the environment with its identifier and configuration.
    - API setup for interaction, execution, validation.
  - Setup environment to default initial state (via `reset()`).

### 1.3. Initialize Per-Environment Data
- For each environment:
  - Store environment object.
  - Store the set of problem NL descriptions.
  - Store ground-truth PDDL domain and problems.
  - Prepare storage for final models, plans, and metrics (e.g., success rate, EW scores).

---

## 2. Interaction Modules & Components

### 2.1. PromptManager
- Instantiate `PromptManager` with templates from `config.yaml`.
- Capable of generating:
  - Initial prompts for PDDL domain/problem generation.
  - Refinement prompts incorporating previous PDDL, environment feedback, and exploration walk results.
  - Problem prompts including NL task description and environment object list.

### 2.2. PDDLUtils
- Instantiate `PDDLUtils` for parsing, syntax validation, predicate extraction, and file writing.
- Allows conversion from raw GPT output into validated, executable PDDL files.
- Facilitates debugging or refinement if output has syntax errors.

### 2.3. PlannerInterface
- Instantiate `PlannerInterface` with the path to the classical planner (e.g., FastDownward).
- Can run planner on PDDL files, check if plan exists, and retrieve plans.

---

## 3. Core Loop (Refinement Process)

### 3.1. Initialization of PDDL Files
- For each environment:
  - Generate initial domain (`d0`) and problem (`p0`) NL descriptions or templates.
  - Use GPT-4 API with `initial_prompt_template`:
    - Send NL description with zero temperature (`τ=0`) for deterministic output.
    - Obtain initial `d(0)` and `p(0)` code.
  - Save to temporary files.

### 3.2. Refinement Iterations (`i` in `[1, c_max]`)
- For each iteration:
  - **Candidate Generation:**
    - For each environment:
      - Generate `n_d` candidate domain files via GPT-4:
        - Use `refinement_prompt_template` with previous best `d(i-1)` and feedback.
        - Sampling with temperature `τ=0.7`.
      - Generate `n_p` candidate problem files similarly.
    - Store candidate `(d_{candidate}, p_{candidate})` pairs.
  - **Exploration Walk Sampling:**
    - For each candidate:
      - For each environment:
        - Sample `T_max` (here, 10) random action sequences:
          - For each sequence:
            - Use `E_{d,p}` to check executability:
              - Generate a sequence of actions from environment action interface.
              - Verify executability at each step.
            - Record the sequence if executable.
      - Compute **EW score**:
        - For each candidate in each environment:
          - Calculate the average executability probability over sampled sequences.
        - Aggregate EW scores across environments.
  - **Plan Evaluation:**
    - For each candidate `(d, p)`:
      - Save PDDL files.
      - Run `run_planner()`:
        - If plan found, validate with `V_{d,p}(q)`:
          - If plan validates successfully, mark as successful.
        - Record success/failure.
  - **Candidate Selection:**
    - Choose the candidate with the highest EW score (or some composite metric combining task success and EW).
    - Update `(d(i), p(i))` for next iteration.
  - **Environmental Feedback & Refinement:**
    - Using environment API, obtain feedback:
      - Sample execution sequences.
      - Record action success/failure.
      - Generate feedback messages (`f(c)`) for GPT prompts.
    - Trigger GPT to refine PDDL based on feedback at `i` (via `refinement_prompt_template`):
      - Generate improved `d(i)` and/or `p(i)`.
    - Save refined files for next iteration.

### 3.3. Termination
- After `c_max` iterations or convergence (based on EW scores or plan success):
  - Final models (`d_final`, `p_final`) are selected based on best EW score.

---

## 4. Evaluation & Metrics Collection

### 4.1. Final Problem Solving
- Run the planner on all problems (`p_{1:N}`) with `d_final`.
- For each problem:
  - Run plan search.
  - Validate plan with the environment’s ground-truth validator `V_{d,p}`.
  - Record success (1) or failure (0).

### 4.2. Compute Final Metrics
- **Solve Rate:** 
  - `success_count / N`
  - Compare against `success_threshold` (e.g., 0.5).
- **EW Score:**
  - For each environment and problem, re-sample exploration walks.
  - Calculate average EW scores over the evaluated models.
- **Return Results:**
  - Overall success rate across environments.
  - Per-environment success.
  - Average EW scores.
  - Final PDDL files (optionally for debugging).

---

## 5. Reporting & Output
- Summarize:
  - Final PDDL domain/problem files.
  - Final success rates.
  - Final EW scores.
  - Number of refinement cycles performed.
- Output metrics and optionally save logs/reports (JSON or CSV).

---

## 6. Error Handling & Robustness
- Verify syntax correctness for all GPT outputs before saving.
- Handle failed planner runs gracefully and record failures.
- If PDDL has syntax errors, re-run GPT with correction prompts.
- Incorporate environment exceptions, timeouts, or API errors with retries or fallbacks.
  
---

## 7. Additional Considerations
- Use seed values for reproducibility.
- Log detailed steps for debugging: prompt contents, API responses, PDDL outputs, EW scores, plan outcomes.
- Run multiple seeds (4 as in the paper) for statistical confidence.
- Allow command-line parameters or configuration for flexibility.

---

## Summary
`app.py` is the orchestration script that:
- Loads datasets and environments.
- Generates initial PDDL files via GPT.
- Iteratively refines these files guided by exploration walk EE metrics, environment feedback, and plan success validation.
- Collects and reports on task success, EW scores, and convergence indicators.
- Implements error handling, logging, and reproducibility best practices.

This detailed logic ensures the implementation faithfully reproduces the experimental methodology and results, matching the description and parameters specified in the JSON plan and configuration.
